Strong scaling measures how the speed of the model evolves when the problem size is kept constant and the number of processing units is increased. Every case runs the same configuration with a different number of processors, and the case with the fewest resources is taken as the reference.

For each test the section presents a table with the geometry of every case (tasks, threads and total processing units) together with the throughput obtained and the derived speedup and efficiency, followed by a scalability figure that plots the throughput of every case against the number of processing units. When the model is built from more than one component, the same figure and table are also given for each component separately.

The throughput is expressed as simulated years per day (SYPD) for most models, as simulated days per day (SDPD) for MONARCH and as the integration time in seconds reported by the model for ICON. The tables and figures name that metric with its unit in the column header and on the vertical axis, so a value is never read without knowing whether it is a rate or a duration. The dashed line of the figures is the ideal scaling extrapolated from the reference case. \emph{Speedup} is the ratio between the throughput of a case and that of the reference case, and \emph{efficiency} is the speedup divided by the ratio of processing units: both are dimensionless ratios, a value of one means that the case scales linearly, below one that it scales worse than ideal and above one better than ideal.
