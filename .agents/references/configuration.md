# Configuration reference

## The config chain

`conf/minimal.yml` (per experiment) sets `DEFAULT.CUSTOM_CONFIG` to the project's
`autosubmit/configuration/bootstrap.yml`. That file merges the following, in order:

| # | File | Notes |
|---|---|---|
| 1 | `core/defaults.yml` | shipped defaults, incl. all `APP_TESTS` = `"FALSE"` |
| 2 | `user/model/%DEFAULT.MODEL%/` | the model's `proj.yml` |
| 3 | `user/` | `common.yml`, `platforms.yml`, `autosubmit.yml` |
| 4 | `core/jobs/jobs-execution.yml` | `REMOTE_SETUP`, `REMOTE_INIDATA`, `REMOTE_COMPILATION`, `PREPARE_TESTS` |
| 5 | `core/jobs/model/%DEFAULT.MODEL%/jobs.yml` | model overrides; only `ecearth4` and `hpcw` ship it |
| 6 | `core/jobs/jobs-hwbenchmarks.yml` | **commented out by default** |
| 7 | `core/jobs/model/<M>/jobs-strongscaling.yml` | enabled by default |
| 8 | `core/jobs/model/<M>/jobs-compilationefficiency.yml` | enabled by default |
| 9 | `core/jobs/model/<M>/jobs-tracing.yml` | commented out by default |
| 10 | `core/jobs/model/<M>/jobs-weakscaling.yml` | commented out by default |
| 11 | `core/jobs/jobs-common.yml` | `CLEAN`, `SYNCHRONIZE`, `REPORT` |
| 12 | `core/platforms/%DEFAULT.HPCARCH%.yml` | sets `DEFAULT.LOGIN_PLATFORM` etc. |

Then `DEFAULT.CUSTOM_CONFIG.POST` loads `~/platforms_credentials.yml` (your `PLATFORMS.*.USER`).

`conf/metadata/experiment_data.yml` is Autosubmit's own resolved-config dump — it is **not** an input
to the chain. Editing it has no effect on a run.

Because the chain is ordered, later files win. `jobs-common.yml` (11) is merged *after* the per-test
files, which is why `REPORT`'s dependency list in `jobs-common.yml` is the one that counts.

## Project files

| Path | Role |
|---|---|
| `autosubmit/configuration/bootstrap.yml` | chain entry point; **enable/disable tests here** |
| `autosubmit/configuration/core/defaults.yml` | `EXPERIMENT` (incl. `APP_TESTS`), `COMMON`, `COMMON_PATH_LOCATIONS`, `MODEL.STORE`, `PARAMETERS_ENV_CONFIG`, `PROJECT_FLAGS` |
| `core/jobs/jobs-common.yml` | `CLEAN`, `SYNCHRONIZE` (`PLATFORM: local`), `REPORT` |
| `core/jobs/jobs-execution.yml` | the model-agnostic setup chain for models not driven by their own Autosubmit config |
| `core/jobs/jobs-hwbenchmarks.yml` | `HW_REMOTE_SETUP`, `HW_COMPILATION`, `PREPARE_TESTS`, `OSU_RUN`, `STREAM`, `POST_HW_BENCHMARKS` |
| `core/jobs/model/<MODEL>/jobs.yml` | model-specific job overrides |
| `core/jobs/model/<MODEL>/jobs-<test>.yml` | one per test: `SCALABILITY_<TEST>` (or `SIM_<TEST>`) → `POST_<TEST>` → `CONFIGURATION_JSON_<TEST>` |
| `core/platforms/<HPCARCH>.yml` | platform-level Autosubmit defaults (picked up via `HPCARCH`) |
| `core/jobs/platform/<HPCARCH>/jobs.yml` | **not loaded** by `bootstrap.yml` — dead unless something else includes it |
| `user/autosubmit.yml` | Autosubmit runtime: `CONFIG` (`MAXWAITINGJOBS`, `TOTALJOBS`, `RETRIALS`, `OUTPUT`), `MAIL`, `COMMUNICATIONS`, `STORAGE`, `MIGRATE` |
| `user/common.yml` | `REPORT`, `HW_BENCHMARKS`, `TRACING` |
| `user/platforms.yml` | `PLATFORMS` definitions |
| `user/model/<MODEL>/proj.yml` | model + per-test specs (`MODEL.STORE` for `hpcw`) |
| `user/platforms_monarch.yml`, `user/model/monarch/proj_monarch.yml`, `core/jobs/model/monarch/jobs.yml` | auto-generated by `cfg/utils/monarch/copy_experiments.py` and git-ignored |

### `core/defaults.yml` keys

`EXPERIMENT.APP_TESTS.{STRONGSCALING,WEAKSCALING,TRACING,COMPILATION_EFFICIENCY}.ENABLED` (all
`"FALSE"`); `EXPERIMENT.DATELIST`/`MEMBERS`/`CHUNKSIZEUNIT`/`CHUNKSIZE`/`NUMCHUNKS`/`CALENDAR`
(placeholders Autosubmit requires — do not repurpose); `COMMON` (`GIT_REPO`, `REFRESH_GIT_REPO`,
`CONFIGURATION`, `EXP_ROOT`); `COMMON_PATH_LOCATIONS` (`PROJECT_ROOT`, `INIDATA_ROOT`,
`BINARIES_ROOT`, `RUN_ROOT`, `COMPILATION_ROOT`, `PROVIDED_TRACES_PATH`, `CFG`); `MODEL.STORE`
(default `""`, set by `user/model/hpcw/proj.yml`);
`PARAMETERS_ENV_CONFIG` (`CONVERT_PARAM_FILE`, `CONFIG_FOLDER`); `PROJECT_FLAGS.MODEL_CONFIG_FOLDER`.

### Models

| Model | `jobs.yml` | Tests shipped | Comps |
|---|---|---|---|
| `ecearth4` | yes (lowercase `jobs:` key — see troubleshooting) | strong, weak, compilationefficiency, tracing | ec-earth |
| `hpcw` | yes | strong, weak, compilationefficiency, tracing | `[nemo, icon]` |
| `nemo` | no | strong, weak, compilationefficiency, tracing | `[nemo]` |
| `monarch` | no (auto-generated, git-ignored) | strong, compilationefficiency, tracing | — |

`configurations/model/` holds `ecearth4`, `harmonie`, `nemo`, `oifs` — not `hpcw`/`monarch`.

### `user/platforms.yml` keys

`TYPE`, `VERSION`, `HOST`, `PROJECT`, `USER`, `QUEUE`, `SCRATCH_DIR`, `ADD_PROJECT_TO_HOST`, plus
per-type extras (`EC_QUEUE`, `CUSTOM_DIRECTIVES`, `PROCESSORS_PER_NODE`, `MAX_WALLCLOCK`,
`MAX_PROCESSORS`, `TEMP_DIR`). Shipped platforms: `hpc2020` (ecaccess/slurm), `mn5` (slurm),
`mn5-login` (`ps`). `USER: "TOFILL"` marks a platform awaiting `~/platforms_credentials.yml`.

## `proj.yml` structure

Common to all models:

- `MODEL` — `NAME`, `COMPONENTS`, `REPORT_COMPONENTS`, `ORIGIN`, `BRANCH`, `ARCH_NAMES` (plus
  `STORE` for `hpcw`: the shared ExternalData object cache of the model)
- `EXPERIMENT` — `RESOLUTION`, `TEST_STEPS`, `OUTPUT` (+ model extras such as `COMPONENT`,
  `TEST_CONFIG`)
- Per-test spec — `TEST_NAMES`, `NAMES`, `PROCESSORS`, `THREADS`, `TEST_CONFIG`, `ARCH_NAME`

Per-test extras actually present today:

- `WEAKSCALING`: `BASE_PROCS`, `BASE_RESOLUTION`, and a `RESOLUTION` list (drives the extra
  `RESOLUTION` key in the weak-scaling `FOR` block)
- `TRACING`: `TIMESTEP_ZERO`, `TRACE_STEPS`, `USER_FUNCTIONS_PROC`, `USER_FUNCTIONS_THREADS`,
  `TRACE_N_FUNCTIONS`
- `STRONGSCALING`: `COUPLING_REPORT` (`ecearth4` only — enables the LUCIA coupling section)

`COMPILATION_EFFICIENCY` takes its arch name **from `TEST_NAMES`**, not from `ARCH_NAME`.

Models differ in which sections they define: `hpcw` and `monarch` carry `EXPERIMENT` (and
`monarch` has no `WEAKSCALING` section at all).

## `ARCH_NAMES` and arch files

`MODEL.ARCH_NAMES` is both the `REMOTE_COMPILATION` `FOR` list and the set of arch prefixes to
build. Arch files live in `cfg/arch/<platform>/<MODEL>/`:

- `hpcw`: `<component>/<ARCH_NAME>.cmake` + `<component>/<ARCH_NAME>.env`, where `<component>` is
  `EXPERIMENT.COMPONENT` (`nemo` or `icon`)
- `monarch`: `<ARCH_NAME>.cmake` + `<ARCH_NAME>.env`
- `nemo`: `arch-<ARCH_NAME>.fcm`

`MODEL.REPORT_COMPONENTS` decides which component sections the report emits and is passed to
`collector.py --components`.
